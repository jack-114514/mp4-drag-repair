MP4一拖修复 v1.2.10 — 批量筛选和修复 MP4

用途
把猫抓下载的 .vss、.ssv、.css、.ts，以及后缀被改成 MP4 的视频，转换为真正的标准 MP4。
根据文件真实内容判断，不能凭扩展名断定文件格式。

直接使用
打开“程序”目录内 v1.2.10 文件夹中的 EXE，再把文件拖入窗口。
窗口较小时，将鼠标移到右侧设置区，用滚轮查看下方选项。
鼠标在开关上停留片刻，会显示勾选后的效果。
默认“自动修复 + 均衡 + 快速检查”。支持多文件、文件夹、重试和自选输出目录。
普通模式默认输出“原名_正常版.mp4”，同名时依次加（1）、（2）等编号。

批量智能筛选
先勾选“批量智能筛选”，再拖入多个文件或一个文件夹。任务列表会显示修复、跳过和失败的数量。
程序按实际内容识别封装和编码。通过结构、H.264/AAC 兼容性和解码检查的普通 MP4 会跳过。
默认快速检查，抽查关键位置以节省时间。选“完整检查”可逐帧筛查源文件。
分片 MP4、实际为 TS/MOV 的 .mp4 文件等，可在读到完整音视频轨道时重新封装为标准 MP4。
默认替换修复成功的源文件，沿用原文件主名，其他扩展名改为 .mp4。替换前默认全片解码验证输出。
大文件想缩短替换等待时间，可勾选“快速替换验证”并使用“快速检查”。
程序仍检查输出结构、编码、时长及可用帧数，并抽查关键位置解码。要逐帧检查，请选“完整检查”。
已有同名 MP4 时，依次保存为“原名（1）.mp4”、“原名（2）.mp4”等，保留已有 MP4。无法读取或验证失败时保留源文件。可取消“替换原文件”以另存结果。
每次提交智能筛选会在程序的“日志”文件夹中保存一份批量日志。普通修复每个文件保存一份。
点击右侧“查看日志”或任务列表下方的“日志目录”，可在资源管理器中浏览程序的日志文件夹。
批次结束后，“修复建议”弹窗会列出失败原因。可按建议切换修复方式重试，或选择其他输出目录。
点击“重试失败”可重新处理任务列表中的失败项。

降分辨率
选中任务后点击“降分辨率”，或直接用此按钮选择视频。
可选 480p、720p、1080p、2K（1440p）、4K（2160p）中低于源视频的档位。横竖屏均按短边比较，保留画面比例。
降分辨率默认使用“速度优先”，也可选“均衡”或“画质优先”。兼容的视频可用 NVIDIA 显卡解码、缩放和编码。
仅在输出小于源视频时另存 MP4，原文件保留。

资源限制
点击右侧“资源限制”，分别设置 CPU、内存和 GPU 百分比。三项默认不限，保存后用于新提交或重试的任务。
CPU 上限按整机 CPU 容量换算。内存上限按电脑的总物理内存计算，限制处理进程可提交的内存。越低越可能遇到分配失败，原文件会保留。
GPU 目标通过间歇限速降低硬件转码的平均占用。任务管理器上的瞬时读数可能更高。降低占用会延长处理时间。

其他可选设置
“使用原文件名”在另存遇到重名时自动编号。
关闭“使用 GPU 加速”可强制用 CPU 转码。勾选“全部成功后自动关闭”后，队列修复或跳过完毕会关闭窗口。
遇到失败或取消时，窗口会保持打开，便于查看结果。

发给别人
分享时请发送 v1.2.10 的整个程序文件夹，其中的 EXE 可以直接运行。
程序文件夹包含运行依赖，可省去单文件版每次启动时的解包。
支持 Windows 10 / Windows 11 的 Intel/AMD 64 位电脑，不支持 macOS、Linux 或 32 位 Windows。
已经打包 Python 运行环境、FFmpeg/FFprobe、界面和拖放组件；不需要别人再安装这些依赖。
不需要联网，不依赖你的用户名、视频目录或 GPU 型号。

CPU 与 GPU 自动选择
自动显示 CPU、逻辑线程数、GPU 型号。
需要重新编码时实际运行小样例测试 NVIDIA NVENC、Intel Quick Sync 或 AMD AMF；可用才采用。
硬件不可用或当前文件硬件处理失败时回退 CPU。NVIDIA 可优先用 CUDA 解码，失败时改用 CPU 解码。
H.264 兼容文件优先无损封装，直接复制编码数据，不需要 GPU 重新编码。
本机 RTX 2060 的硬件路径和 CPU 软件回退已实测；没有在其他型号实体电脑上实测。

处理方式与速度
自动修复：优先无损封装，必要时转换 H.264/AAC，保留分辨率、帧率。
遇到被标记异常的 MPEG-TS 数据包时，保留数据包重试。转码遇到重复时间戳时，修正视频时间戳后重试。这两种重试成功后均须通过全片解码验证。
仅无损封装：不重新编码视频；不兼容的视频会提示改用自动修复。
强制转换 H.264：即使原本兼容，也重新编码；通常不必选择。
均衡、速度优先、画质优先三档只影响重新编码。速度优先可能改变压缩效率和细节表现。
NVIDIA 使用 CQ18；软件使用 x264 CRF18。转码为有损操作，无损封装不损失画质。
转码输出约每 2 秒一个关键帧，改善拖动进度和检查时的等待。
索引预留在文件开头，避免写完后再搬移整片；预留不足则用同编码设置回退 faststart。
预留空余部分是合法 free atom，文件会增加少量空间，不影响视频内容。

时间预测
分析视频后显示当前文件的初步总用时范围。筛选、封装、转码和验证分别估算，处理时按当前阶段的近期实际速度更新。
“全部剩余”把当前文件和已排队文件的预估时间相加。排队文件按同一组设置下的处理速度和文件大小粗估，混合不同编码时波动可能较大。
本机保存不含文件名或视频内容的平均速度，用于后续估算。
预计时间不是保证，首次估计较粗；磁盘繁忙、关键帧间隔和异常文件可能增加耗时。

检查与日志
快速检查：结构、编码、时长、帧数与 5 个位置解码，不代表全片逐帧扫描。
完整检查：逐帧解码，长视频明显更慢。
保留一个主视频与全部音轨，移除封面、字幕、数据轨、章节，优先保证普通 MP4 兼容性。
界面可查看视频信息、打开目录和播放结果。处理日志统一保存在程序目录的“日志”文件夹。

范围
不能凭空补回下载时已丢失的数据，遇到未下载完整的视频仍需要重新下载。
不能解除 Telegram 的账户上传大小限制。Telegram 发送和封面显示由用户手动确认。
本软件在本机处理视频，不上传内容，不读取 Telegram 账户。
